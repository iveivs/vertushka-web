# Архитектура

Код делится на пять слоёв по упрощённому [Feature-Sliced Design](https://feature-sliced.design/ru/docs/get-started/overview). Главное правило: **слой импортирует только слои ниже себя**. Тогда, удаляя фичу, ты точно знаешь, что больше ничего не сломается.

```
src/
├── app/        ↓  запуск приложения: провайдеры, глобальные стили, карта маршрутов
├── pages/      ↓  экран под один маршрут: собирает фичи и сущности, своей логики почти нет
├── features/   ↓  действие пользователя: лайк, поиск, комментарий, вход
├── entities/   ↓  сущность: как получить и показать пластинку, пользователя, комментарий
└── shared/        без бизнес-смысла: клиент API и типы, UI-кит, общие хуки, конфиг
```

Стрелка — направление импорта. Обратно (`shared` из `entities` — можно, `entities` из `shared` — нельзя) и вбок (фича из фичи) импортировать нельзя.

| Слой | Примеры модулей |
| --- | --- |
| `pages` | `feed`, `record`, `profile`, `login`, `not-found` |
| `features` | `like-record`, `search-records`, `add-comment`, `auth` |
| `entities` | `record` (RecordCard), `user` (UserAvatar), `comment` |
| `shared` | `api`, `ui`, `lib`, `config` |

Внутри слоя код делится на модули: `features/like-record/`. Наружу модуль отдаёт только то, что экспортирует его `index.ts`. Импорт «вглубь» чужого модуля, в обход `index.ts`, запрещён.

## Маршруты

| Путь | Страница | Доступ |
| --- | --- | --- |
| `/` | Лента пластинок: поиск, фильтры, сортировка | Все |
| `/records/:id` | Пластинка и комментарии | Все |
| `/records/new` | Добавить пластинку | Только вошедшие |
| `/records/:id/edit` | Редактировать свою пластинку | Только владелец |
| `/users/:username` | Профиль и фонотека пользователя | Все |
| `/login`, `/register` | Вход и регистрация | Только гости |
| `*` | Страница 404 | Все |

Параметры поиска и фильтров живут в адресной строке (`/?search=miles&genre=jazz&page=2`), а не в стейте. Так ссылкой на выдачу можно поделиться, а кнопка «Назад» работает.

## Где хранятся данные

| Какие данные | Где | Пример |
| --- | --- | --- |
| Пришли с сервера | Кеш TanStack Query | Лента, пластинка, комментарии, профиль |
| Состояние в адресе | URL-параметры | Поиск, фильтры, страница |
| Нужны всему приложению, не с сервера | Zustand | Токен и текущий пользователь |
| Нужны одному компоненту | `useState` | Открыто ли меню, текст в поле до отправки |

Данные с сервера **никогда** не копируются в Zustand или `useState`. Две копии одних данных рано или поздно расходятся.

Все запросы к API идут через один клиент в `shared/api`. Он подставляет адрес из `VITE_API_URL` и токен, разбирает формат ошибки. Голый `fetch` в компонентах запрещён.
