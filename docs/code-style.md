# Код-стайл и Definition of Done

Оформление кода не обсуждаем на ревью: за него отвечают Prettier и ESLint. На ревью обсуждаем смысл.

## Именование

| Что | Как | Пример |
| --- | --- | --- |
| Компонент и его файл | PascalCase | `RecordCard.tsx` |
| Хук | camelCase с `use` | `useDebounce.ts` |
| Остальные файлы и папки | kebab-case | `api-client.ts`, `record-card/` |
| Переменные и функции | camelCase, по смыслу | `likedRecords`, не `arr2` |
| Константы | UPPER_SNAKE_CASE | `PAGE_SIZE` |
| Типы | PascalCase, без префикса `I` | `Record`, не `IRecord` |

## Правила

- Только TypeScript, никаких `any`. Не знаешь тип — спроси или используй `unknown`.
- Один компонент — один файл. Компонент длиннее ~150 строк — сигнал разбить его.
- Никаких адресов API, «магических» чисел и строк прямо в компонентах — выносим в константы или конфиг.
- Цвета, размеры и отступы — только через CSS-переменные (дизайн-токены).
- Никаких `console.log` в PR.
- Закомментированный код не коммитим: история есть в Git.
- Тексты интерфейса на русском, код и коммиты на английском.

## Definition of Done

Задача считается сделанной, когда:

- [ ] Выполнены все критерии приёмки из issue
- [ ] `npm run lint` и `npm run build` проходят без ошибок
- [ ] Вёрстка проверена на ширине 360 px и 1440 px
- [ ] В консоли браузера нет ошибок и предупреждений
- [ ] PR оформлен по шаблону, в описании есть `Closes #…`, ветка свежая относительно `main`
- [ ] Ты сам перечитал свой диф на GitHub перед тем, как звать на ревью
