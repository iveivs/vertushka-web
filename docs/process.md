# Как мы работаем с задачами

Задачи живут в [Issues](https://github.com/iveivs/vertushka-web/issues), их статус виден на доске в [Projects](https://github.com/iveivs/vertushka-web/projects). Каждая задача закрывается своим PR, поэтому история проекта складывается сама: задача → PR → ревью → мёрж.

## Путь задачи

| Колонка | Что значит | Кто переносит |
| --- | --- | --- |
| Backlog | Задача заведена, но в текущий спринт не входит | Тимлид |
| To Do | Входит в спринт, можно брать | Тимлид |
| In Progress | Ты над ней работаешь. Одновременно — не больше одной | Ты, когда начал |
| Review | Открыт PR, ждёт ревью или исправлений | Ты, когда открыл PR |
| Done | PR влит, issue закрыт | Автоматически при мёрже |

Задачи берутся сверху вниз по номеру, если тимлид не сказал иначе.

## Как устроена задача

- **Заголовок** — что нужно получить, а не что делать: «Дизайн-токены и глобальные стили».
- **Описание** — зачем это нужно, критерии приёмки чекбоксами, что почитать, вопрос «Подумай».
- **Критерии приёмки** — контракт. Задача готова, когда выполнены все пункты и [Definition of Done](code-style.md#definition-of-done). Отмечай чекбоксы по ходу работы.
- **Вопросы по задаче** задавай комментарием в самом issue. Так обсуждение останется рядом с задачей.

## Метки

| Метка | Значит |
| --- | --- |
| `type: feature` | Новая функциональность |
| `type: chore` | Настройка, зависимости, конфиги |
| `type: docs` | Документация |
| `type: bug` | Что-то сломано |
| `type: refactor` | Переделка без изменения поведения |
| `size: S` / `M` / `L` | Оценка: до 2 ч / 2–4 ч / больше 4 ч |
| `blocked` | Ждёт внешнего: ответа, бэкенда, решения |
| `backend` | Нужна правка в `vertushka-api` |

Если задача оказалась больше оценки в 2 раза — это нормально, но напиши об этом в issue. Это тоже рабочая информация.

## Спринты

Спринт — это [Milestone](https://github.com/iveivs/vertushka-web/milestones) со сроком. На странице майлстоуна видно, сколько задач спринта уже закрыто. В конце спринта короткая ретро: что получилось, что мешало, что меняем.

## Нашёл баг или проблему

Заведи issue сам: что делал, что ожидал, что получил, скриншот. Метка `type: bug`. Если проблема в API — метка `backend`, issue заводится в [vertushka-api](https://github.com/iveivs/vertushka-api/issues).
